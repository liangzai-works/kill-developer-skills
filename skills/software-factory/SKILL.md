# 软件工厂 (Software Factory)

> 把一段需求, 端到端变成: 文档 + 可运行软件 + 验证 + 交付。
> 所有产物命名遵循 `NN_<项目名>_<文档名>.<ext>`。

## 1. 它做什么

`software-factory` 是元技能本身不写代码, 编排能力调用其他 Skill 完成。
按阶段产出可读、可追溯、可复盘的产物。

## 2. 不做什么

- 不重写已有 Skill 能力
- 不在用户没授权时擅自做技术决策
- 不为节省 token 跳过阶段 (token 紧张时压缩, 不跳过)

## 3. 输入

```yaml
user_input:
  text: "项目需求原文"             # 必填
  project_name: "可选, 若缺省从原文首句主题词取"
  workspace_dir: "DEMO工作空间/"  # 缺省按 "<项目名>工作空间/" 建
```

## 4. 工作空间结构

```
<项目名>工作空间/
├── 01_<项目名>_需求规格说明书.md
├── 详细设计模板.docx         (可选, 若有则作为详细设计的样式基线)
├── 02_<项目名>_详细设计文档.docx     (优先用上方 .docx 模板)
├── 03_<项目名>_架构设计.md            (架构图/部署图/时序图)
├── 04_<项目名>_数据库设计.md          (有数据库时)
├── 源代码/
│   ├── <项目名>-server/      (后端)
│   └── <项目名>-web/         (前端)
├── 05_<项目名>_测试报告.md
├── 06_<项目名>_验收报告.md
├── 07_<项目名>_交付报告.md
└── screenshots/
    └── <NN>-<含义>.png
```

**命名约束**:

- `NN` 两位数字前缀, 从 01 起, 表示阶段序号
- `<项目名>` 全大写或驼峰一致, 与 workspace 目录名拼写相同
- 文档名中文, 用 _ 分隔
- 扩展名用文档本应格式 (md / docx / sql / png / 等)

## 5. 详细设计文档特殊处理

```
if 工作空间存在 "详细设计模板.docx":
    使用 docx skill 以该模板为样式基线
    按 9 节标准填充内容: 概述 / 总体设计 / 模块设计 / 接口设计 / 数据库设计 / 界面设计 / 部署运行 / 错误处理 / 附录
    输出 "02_<项目名>_详细设计文档.docx"
else:
    使用 docx skill 默认模板, 直接生成标准 9 节
    输出 "02_<项目名>_详细设计文档.docx"
```

**重要**:

- 调用 `docx` Skill 完成 .docx 生成 (本元技能不自造 Word)
- 模板文件本身不进入 git tracking (用户私有资产)

## 6. 工作流 (Phase)

### Phase 0 - 技能环境准备

- 比对 skill-manifest 与已装 Skills
- 缺失项走 install_mode (interactive / auto)
- 注意: 不读取详细设计模板 (那是 Phase 1 / 4 的事)

### Phase 1 - 需求评估

- 识别 Idea / Spec 模式
- 输出 `01_<项目名>_需求规格说明书.md`
- 缺失项列 `01_<项目名>_需求假设清单.md` (待用户确认)

### Phase 2 - 8 Stage 流水线

| 序号 | 名称 | 必选 | 产出 (在工作空间根) |
|------|------|------|----------------------|
| 1 | 需求规格 | ✅ | 01_<项目名>_需求规格说明书.md |
| 2 | 详细设计 | ✅ | 02_<项目名>_详细设计文档.docx (读"详细设计模板.docx"作为样式基线) |
| 3 | 架构设计 | ✅ | 03_<项目名>_架构设计.md |
| 4 | 数据库设计 | 数据库型必选 | 04_<项目名>_数据库设计.md (含 .sql) |
| 5 | 实现 | ✅ | 源代码/<项目名>-server/ 与源代码/<项目名>-web/ |
| 6 | 构建运行 | ✅ | runtime.log + health-check.json |
| 7 | 浏览器验收 | ✅ (前端型) | 06_<项目名>_验收报告.md + screenshots/*.png |
| 8 | 测试评审 | ✅ | 05_<项目名>_测试报告.md + 08_<项目名>_代码评审报告.md |

> 前端型项目永远不缺 Stage 7 - 即使 hello world, 也要落浏览器验收报告与截图。

## 7. 强制 UI Artifact 规则 (v0.2.0 引入)

任何含有前端 UI 的项目都必须落 UI design artifact:

- 进入 Stage 3 (UI Design) 时, 读取 prompt 强制条款, 生成至少 1 个 HTML 原型 + CSS 变量
- 不允许 skip_when
- token 紧张时, 压缩原型 (单页 + 状态 tab) 而非 skip

## 8. 控制

- pause / resume / rerun_stage 同上
- dry-run: 只到 Phase 1

## 9. 触发方式

```
$software-factory 开发一个简单的留言板
$software-factory --project=DEMO
$software-factory --rerun=stage2
```
